# สเปกหน้าจอ Front-end (อ้างอิงจากเว็บเดิม)

เอกสารนี้อธิบายหน้าจอและพฤติกรรมของเว็บเดิม (Next.js ใน repo นี้) เพื่อให้ทีม front-end สร้างเว็บใหม่ที่แยกออกมา deploy บน Cloudflare Pages ได้ครบเท่าของเดิม และระบุหน้าจอที่ต้องสร้างเพิ่มสำหรับฟีเจอร์ใหม่

- รายละเอียด API ทั้งหมดอยู่ใน [API.md](API.md) เอกสารนี้อ้างถึงเฉพาะ endpoint ที่แต่ละหน้าใช้
- หัวข้อที่มีป้าย **🆕** คือหน้าหรือฟีเจอร์ที่เว็บเดิม**ไม่มี** และต้องสร้างใหม่
- หัวข้อที่มีป้าย **⚠️** คือพฤติกรรมของเว็บเดิมที่**ไม่ควรทำตาม**

## 1. ภาพรวม

ระบบบันทึกรายงานการประชุมของกองระบาดวิทยา ผู้ใช้ login แล้วบันทึกว่าไปประชุมอะไร (หรือจัดประชุมอะไร) พร้อมสรุปเนื้อหา ไฟล์แนบ และติด tag เขตสุขภาพ / ขอบเขตงาน / กลุ่มโรค / โรค เพื่อใช้ค้นหาและทำสถิติ

**เทคโนโลยีของเว็บเดิม** (ใช้เป็นแนวทางได้ ไม่บังคับ)

| ส่วน | ที่ใช้ |
|---|---|
| Framework | Next.js (App Router) + React |
| CSS | Tailwind CSS v4 |
| ฟอนต์ | Bai Jamjuree (Google Fonts, น้ำหนัก 200–700, subset thai + latin) |
| Dropdown ค้นหาได้ (เลือกหลายค่า) | `react-select` |
| Popup แจ้งผล / ยืนยัน | `sweetalert2` |
| กราฟ | `chart.js` + `react-chartjs-2` |
| Debounce ช่องค้นหา | `use-debounce` |

**แผนผังหน้าจอ**

```
/login ─────────────► / (หน้าหลัก: สถิติ + กราฟ + ตารางรายการประชุม)
/register 🆕             ├─► /meetings/new           (สร้างรายงาน)
                         ├─► /meetings/{id}          (รายละเอียด)
                         │      └─► /meetings/{id}/edit  (แก้ไข)
                         ├─► /profile 🆕             (ข้อมูลส่วนตัว / เปลี่ยนรหัสผ่าน)
                         └─► /admin/users 🆕         (จัดการผู้ใช้ เฉพาะแอดมิน)
```

## 3. Routing และการเข้าถึง

| Route | ใครเข้าได้ | ถ้าไม่มีสิทธิ์ |
|---|---|---|
| `/login` | ทุกคน | ถ้า login อยู่แล้ว → ไป `/` |
| `/register` 🆕 | ทุกคน | ถ้า login อยู่แล้ว → ไป `/` |
| `/` | login แล้ว | ไป `/login` |
| `/meetings/new` | login แล้ว | ไป `/login` |
| `/meetings/{id}` | login แล้ว | ไป `/login` |
| `/meetings/{id}/edit` | login แล้ว | ไป `/login` |
| `/profile` 🆕 | login แล้ว | ไป `/login` |
| `/admin/users` 🆕 | `role = ADMIN` | ไม่ใช่แอดมิน → ไป `/` และซ่อนเมนู |

**การจัดการ token**

- หลัง login เก็บ `accessToken` (ดู [API.md ข้อ 3](API.md#3-การยืนยันตัวตน))
- ตอนเปิดแอปให้เรียก `GET /me` เพื่อตรวจว่า token ยังใช้ได้ และได้ข้อมูลผู้ใช้ล่าสุด (ชื่อ, role)
- ได้ `401` จาก endpoint ใดก็ตาม → ลบ token แล้วพาไป `/login` (token หมดอายุใน 24 ชั่วโมง หรือผู้ใช้ถูกระงับ)
- ได้ `403` → แจ้งว่าไม่มีสิทธิ์ ไม่ต้อง logout
- `id` ใน URL ที่ไม่ใช่ตัวเลข หรือ API ตอบ `404` → แสดงหน้า "ไม่พบข้อมูล"

## 4. หน้า Login

**Route:** `/login` · **API:** `POST /token`

```
┌──────────────────────────────┐
│          เข้าสู่ระบบ            │
│                              │
│  ชื่อผู้ใช้                      │
│  [________________________]  │
│  รหัสผ่าน                      │
│  [________________________]  │
│                              │
│  (ข้อความ error สีแดง)          │
│  [       เข้าสู่ระบบ        ]    │
│                              │
│  ลืมรหัสผ่าน? 🆕   สมัครสมาชิก 🆕 │
└──────────────────────────────┘
```

- การ์ดกลางจอ `max-w-sm` พื้นหลัง `bg-slate-50`
- ทั้งสองช่องเป็น `required`
- error แสดงใต้ฟอร์ม `text-sm text-red-600 text-center` (ไม่ใช่ popup)
- สำเร็จ → ไป `/`

| ผลจาก API | ข้อความที่แสดง |
|---|---|
| 401 `INVALID` | ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง |
| 403 `PENDING` | บัญชีของคุณอยู่ระหว่างรอผู้ดูแลระบบอนุมัติ |
| 403 `NOT_ALLOWED` | บัญชีของคุณไม่ได้รับอนุญาตให้ใช้งาน |

ใช้ `message` จาก API แสดงได้เลยทุกกรณี

🆕 **เพิ่มจากเว็บเดิม**
- ลิงก์ **"ลืมรหัสผ่าน?"** → แสดงข้อความ (popup หรือข้อความใต้ฟอร์ม): *"กรุณาติดต่อผู้ดูแลระบบเพื่อรีเซ็ตรหัสผ่าน"* ไม่มีระบบรีเซ็ตเอง
- ลิงก์ **"สมัครสมาชิก"** → `/register`
- ปุ่มควร disabled และแสดง "กำลังเข้าสู่ระบบ..." ระหว่างรอ

### 5.1 Header

- ซ้าย: ชื่อระบบ
- ขวา: "สวัสดี, {username}!" (ซ่อนบนจอเล็ก `hidden sm:block`) + ปุ่ม "ออกจากระบบ"
- ออกจากระบบ = ลบ token แล้วไป `/login` (ไม่ต้องเรียก API)
- 🆕 เพิ่มเมนู "ข้อมูลส่วนตัว" (`/profile`) และ "จัดการผู้ใช้" (`/admin/users` แสดงเฉพาะแอดมิน) ถ้าเป็นแอดมินควรมี badge จำนวนผู้ใช้รออนุมัติ (`GET /users?status=PENDING&pageSize=1` → `pagination.total`)

### 5.2 Stat card

- "รายงานทั้งหมด" ใช้ `data.total` จาก `/stats/meetings-by-organizer`
- เว็บเดิมเว้นที่ไว้ให้เพิ่มการ์ดอื่นภายหลัง (grid 4 คอลัมน์)

### 5.3 กราฟ

- กราฟแท่ง (Bar) ข้อมูลจาก `data.byOrganizer` แกน X = `name`, แกน Y = `count`
- title: "จำนวนประชุมตามหน่วยงานผู้จัด" (ขนาด 18), legend: "จำนวนประชุม" ด้านบน
- สีแท่ง `rgba(14,165,233,0.6)` เส้นขอบ `rgba(14,165,233,1)` (sky-500)
- แกน Y เริ่มที่ 0, step = 1 (จำนวนเต็ม)
- สูง 350px, responsive, ใช้ฟอนต์เดียวกับหน้า (`family: "inherit"`)
- กราฟแสดงข้อมูลทั้งหมด ไม่ได้กรองตามช่องค้นหา
- ผู้จัดมี 49 หน่วยงาน ชื่อยาว ถ้าแกน X อ่านยากพิจารณาใช้กราฟแท่งแนวนอน หรือแสดงเฉพาะ 10 อันดับแรก

### 5.4 ค้นหาและกรอง

| Control | พฤติกรรม |
|---|---|
| ช่องค้นหา | placeholder "ค้นหาชื่อเรื่องการประชุม..." debounce 300ms → ส่ง `search` |
| Dropdown ผู้จัด | ตัวเลือกแรก "-- กรองตามผู้จัดทั้งหมด --" (ค่าว่าง) ตามด้วยรายชื่อผู้จัดจาก `lookups.organizers` → ส่ง `organizerId` |

- เปลี่ยนค่าค้นหาหรือตัวกรอง → **กลับไปหน้า 1** เสมอ
- เก็บ `page`, `search`, `organizerId` ไว้ใน **query string ของ URL** (เช่น `/?page=2&search=ไข้&organizerId=3`) เพื่อให้กด back / refresh / แชร์ลิงก์แล้วได้ผลเดิม และค่าใน input ต้องอ่านกลับจาก URL ตอนโหลดหน้า

### 5.5 ตาราง

| คอลัมน์ | ข้อมูล |
|---|---|
| เรื่อง | `title` |
| ผู้จัด | `organizer.name` |
| วันที่เริ่ม | `startDate` (รูปแบบสั้น) |
| วันที่สิ้นสุด | `endDate` (รูปแบบสั้น) |
| (ไม่มีหัว) | ลิงก์ "ดูรายละเอียด" → `/meetings/{id}` ชิดขวา |

- เรียง `startDate` ใหม่ → เก่า (API เรียงให้แล้ว) 20 รายการต่อหน้า
- ไม่มีข้อมูล → แถวเดียวกลางตาราง "ไม่พบข้อมูลที่ตรงกับเงื่อนไข"
- hover แถว `hover:bg-slate-50` ตารางเลื่อนแนวนอนได้บนจอเล็ก (`overflow-x-auto`)

### 5.6 Pagination

- ปุ่ม "← หน้าก่อนหน้า" / "หน้าถัดไป →" และข้อความ "หน้า {page} จาก {totalPages}"
- ปิดปุ่มก่อนหน้าเมื่อ `page <= 1` และปุ่มถัดไปเมื่อ `page >= totalPages`
- ⚠️ ถ้า `totalPages = 0` เว็บเดิมแสดง "หน้า 1 จาก 0" ควรซ่อน pagination หรือแสดง "หน้า 1 จาก 1"

### 7.2 โหมดแก้ไข

- โหลด `GET /meetings/{id}` แล้วเติมค่าทุกช่อง checkbox ใช้ `data.objectives.map(o => o.id)` เป็นต้น วันที่ใช้ `startDate.slice(0, 10)`
- **ไม่แสดง**ส่วนไฟล์แนบ เพราะ API แก้ไฟล์ไม่ได้ 🆕 แนะนำแสดงลิงก์ไฟล์เดิมแบบอ่านอย่างเดียวแทน
- `PUT` เป็นการแทนที่ทั้งหมด ต้องส่งทุก field รวมทุก checkbox ที่ติ๊กอยู่

### 7.3 การส่งฟอร์ม

1. ปุ่มชิดขวาล่าง: "บันทึกรายงาน" (สร้าง) / "อัปเดตรายงาน" (แก้ไข) ระหว่างส่งแสดง "กำลังบันทึก..." และ disabled
2. สร้าง `FormData` (ดูวิธีส่ง `*Ids` หลายค่าใน [API.md ข้อ 7.3](API.md#73-สร้างรายงาน))
3. สำเร็จ → popup "สำเร็จ!" "บันทึกรายงานการประชุมเรียบร้อยแล้ว" (2 วินาที) แล้ว
   - โหมดสร้าง → ไป `/`
   - โหมดแก้ไข → ไป `/meetings/{id}`
4. ผิดพลาด → popup error พร้อม `message` จาก API

### 7.4 🆕 Validation ฝั่ง front-end ที่ควรเพิ่ม

เว็บเดิมพึ่ง `required` ของ HTML และ API เป็นหลัก ควรเพิ่มให้ผู้ใช้เห็นปัญหาก่อนกดส่ง

| เงื่อนไข | ข้อความแนะนำ |
|---|---|
| ไม่ได้ติ๊กวัตถุประสงค์เลย | กรุณาเลือกวัตถุประสงค์การประชุมอย่างน้อยหนึ่งข้อ |
| `endDate` ก่อน `startDate` | วันที่สิ้นสุดต้องไม่ก่อนวันที่เริ่ม |
| ไฟล์เกิน 10MB หรือชนิดไม่ตรง | ไฟล์ {ชื่อ} มีขนาดใหญ่เกิน 10MB / ไม่ใช่ประเภทไฟล์ที่อนุญาต |
| `title` ยาวเกิน 255 ตัวอักษร | ใส่ `maxLength={255}` |
| ติ๊ก "อื่นๆ โปรดระบุ" แต่ไม่กรอกช่องอื่นๆ | กรุณาระบุรายละเอียด |

แนะนำ: แสดงช่อง `otherScope` / `otherDiseaseGroup` เฉพาะเมื่อติ๊กตัวเลือกที่ชื่อ "อื่นๆ โปรดระบุ" (เว็บเดิมแสดงตลอด)

### 8.1 สมัครสมาชิก `/register`

**API:** `POST /register`

| Field | Control | บังคับ |
|---|---|---|
| `username` | Text "ชื่อผู้ใช้" | ✔ |
| `password` | Password "รหัสผ่าน" (อย่างน้อย 8 ตัว) | ✔ |
| (ยืนยันรหัสผ่าน) | Password ตรวจฝั่ง front-end ว่าตรงกัน ไม่ส่ง API | ✔ |
| `name` | Text "ชื่อ-นามสกุล" | แนะนำให้บังคับ เพื่อให้แอดมินรู้ว่าใคร |
| `department` | Text "หน่วยงาน" | |
| `email` | Email "อีเมล" | |

- สำเร็จ → แสดงข้อความ **"สมัครสมาชิกสำเร็จ กรุณารอผู้ดูแลระบบอนุมัติ"** แล้วให้ลิงก์กลับไป `/login` (ไม่ต้อง login อัตโนมัติ)
- `409` → "ชื่อผู้ใช้นี้ถูกใช้งานแล้ว" แสดงใต้ช่อง username

### 8.2 ข้อมูลส่วนตัว `/profile`

**API:** `GET /me`, `PATCH /me`

แบ่งเป็น 2 การ์ด

1. **ข้อมูลส่วนตัว:** `username` (อ่านอย่างเดียว), `role`, `status` (อ่านอย่างเดียว), `name`, `department`, `email` (แก้ได้) → ปุ่ม "บันทึก"
2. **เปลี่ยนรหัสผ่าน:** รหัสผ่านปัจจุบัน (`currentPassword`), รหัสผ่านใหม่ (`newPassword` ≥8), ยืนยันรหัสผ่านใหม่ → ปุ่ม "เปลี่ยนรหัสผ่าน" สำเร็จแล้วล้างช่องทั้งหมด

### 8.3 จัดการผู้ใช้ `/admin/users` (แอดมินเท่านั้น)

**API:** `GET /users`, `POST /users`, `PATCH /users/{id}`, `DELETE /users/{id}`, `POST /users/{id}/approve`, `POST /users/{id}/reject`

```
 จัดการผู้ใช้                                           [+ เพิ่มผู้ใช้]
 [ รออนุมัติ (3) | ใช้งานอยู่ | ถูกปฏิเสธ | ถูกระงับ | ทั้งหมด ]   ← แท็บ = ตัวกรอง status
 [ค้นหาชื่อผู้ใช้ / ชื่อ / อีเมล...]  [-- ทุกสิทธิ์ -- ▾]
 ┌──────────┬───────────┬──────────┬───────┬──────────┬───────────┬──────────────────┐
```

**ป้ายสถานะ (แนะนำสี)**

| `status` | ข้อความ | สี |
|---|---|---|
| `PENDING` | รออนุมัติ | เหลือง |
| `APPROVED` | ใช้งานอยู่ | เขียว |
| `REJECTED` | ไม่อนุมัติ | เทา |
| `SUSPENDED` | ถูกระงับ | แดง |

**ปุ่มตามสถานะ**

| สถานะ | ปุ่ม | API |
|---|---|---|
| `PENDING` | อนุมัติ / ไม่อนุมัติ | `POST /users/{id}/approve` / `reject` |
| `APPROVED` | แก้ไข / ระงับ / ลบ | `PATCH` / `PATCH {status:"SUSPENDED"}` / `DELETE` |

- ลบ / ระงับ / ไม่อนุมัติ ต้องมี popup ยืนยันก่อน แนะนำให้ใช้ "ระงับ" แทน "ลบ" ถ้าต้องการเก็บประวัติ
- ซ่อนปุ่มลบ / ระงับ / เปลี่ยนสิทธิ์ ในแถวของ**ตัวเอง** (API ไม่ยอมอยู่แล้ว แต่ไม่ควรให้กด)
- แท็บ "รออนุมัติ" ควรเป็นแท็บแรก และแสดงจำนวนจาก `pagination.total`
